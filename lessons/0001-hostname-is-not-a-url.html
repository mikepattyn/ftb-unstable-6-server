Mission · Reference

Lesson 0001 · ~8 minutes

A hostname is not a URL

Friends will type ftb-unstable.mikepattyn.nl. That string is a DNS name. Minecraft is not a browser, so they must not type https://….

What you will be able to do

Write the one DNS record that turns ftb-unstable.mikepattyn.nl into your home public IPv4 — and explain why the port is not part of that record.

Two different strings

A URL starts with a scheme. https://mikepattyn.nl/about tells a browser: use HTTPS, talk to that host, request that path. That grammar is RFC 3986.

A hostname is only the name: ftb-unstable.mikepattyn.nl. DNS looks it up and returns addresses. Minecraft’s server box wants a hostname (optionally :port). The Java wiki says players type the domain in place of the IP — not as a website. [Minecraft Wiki]

Give players: ftb-unstable.mikepattyn.nl
Do not give: https://ftb-unstable.mikepattyn.nl or a LAN address like 192.168.1.20.

The A record is the whole DNS job (on port 25565)

An A record maps a name to one IPv4 address. The record’s data is four dotted decimals. There is no room for a port. [RFC 1035 §3.4.1]

Your Compose file already publishes the Java default, TCP 25565. The client uses that port when the player omits :something. So for this server you do not need an SRV record. SRV is how Java learns a non-default port from DNS. Save that for a later lesson. [Wiki: SRV, RFC 2782]

; name                         ttl  class  type  address
ftb-unstable.mikepattyn.nl.    300  IN     A     YOUR.PUBLIC.IPV4

The wiki is explicit: the A record answer is the server’s external IP, “usually after port forwarding.” [Wiki: A record]

Why the public IP, not the MacBook’s

Friends are not on your Wi-Fi. Their lookup must return an address routers on the public internet can deliver to. Addresses in 192.168.0.0/16, 10.0.0.0/8, and 172.16.0.0/12 are private; they are not globally reachable. [RFC 1918]

Your existing port-forward is what takes a packet that arrived at the public IP and hands it to the Mac. DNS does not do that hop. DNS only answers “which IP is this name?”

1 · NamePlayer types ftb-unstable.mikepattyn.nl
2 · DNSA record → YOUR.PUBLIC.IPV4
3 · Port (client default)TCP 25565, unless they typed :other
4 · Your router (already done)WAN 25565 → Mac LAN IP 25565
5 · Docker (already done)Host 25565 → container 25565

Two traps that break “any service at home”

Orange cloud / “proxied” DNS. If the zone lives on Cloudflare (or a similar HTTP proxy), a proxied A record returns Cloudflare IPs and only forwards HTTP/HTTPS. Minecraft is raw TCP. The record must be DNS-only (gray cloud). [Cloudflare: non-HTTP services]

WAN address in 100.64.0.0–100.127.255.255. That block is ISP shared space (CGNAT). A record can still “work” as DNS, but inbound port-forwards on your router will not reach a unique public IP. [RFC 6598] You said the router is already forwarded; still glance at the WAN IP once.

Do this once on your machine

  1. On the router status page (or a “what is my IP” check from the Mac), copy the WAN IPv4. Reject it if it is RFC 1918 or 100.64/10.
  2. Open DNS for mikepattyn.nl (registrar or Cloudflare). Add the A record in the table above. If you see a proxy toggle, leave it off.
  3. Wait a few minutes, then run:
dig +short A ftb-unstable.mikepattyn.nl

You want that command to print the same public IPv4. The wiki’s check is the same idea with dig / nslookup. [Wiki: verify]

Then join from a network that is not your LAN (phone hotspot is fine) using only ftb-unstable.mikepattyn.nl.

Keep

The pocket card is Hostname → home server. Next time the service is SSH, a second Minecraft port, or a website, you change the label and sometimes the port story — not the idea.

If any hop is fuzzy — “where do I click for mikepattyn.nl?”, “dig printed nothing”, “it works on LAN but not for friends” — ask in this chat. That is the point of having a teacher. Next lesson can be the NAT path or Dynamic DNS if your WAN IP moves.
